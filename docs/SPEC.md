作成: 2026-11-14 / 画面モック（3画面）確定を受けて作成
ステータス: アプリ名「うろぼえ」正式決定・Android先行で決定（2026-11-14 本人）。実装開始。

## 1. コンセプト

**覚えたいものだけ残る。忘れていいものは、そっと消える。**

キャッチフレーズ（2026-11-16 本人決定）：**「メモを不要にするメモ帳」** — メモを暗記させることで、メモそのものを不要にする、という逆転を一言で表す。アプリ内では About の冒頭とオンボーディング1枚目に配置する（v0.3.7〜）。

ポジショニング（2026-11-16 本人）：期限を切るほどではないタスク（「いつかやろう」）をメモするのに向くアプリ。コピーは **「『いつかやろう』を『そろそろやろう』に変えるアプリ」**。About とホームの空状態に配置（v0.3.10〜）。オンボーディング2枚目ではタイプ選択（よく忘れる／マルチタスクが苦手／期限に追われたくない）を置き、選んだタイプに「あなたに最適です」と返して、自分向けのアプリだと感じさせる（選択は端末内に保存）。

- メモは「溜める」ものではなく「選別する」もの。書く → 勝手に再会する → 残したいものだけ「暗記する」を押す → 押さなかったものは30日で自然に消える。
- デフォルトの逆転が核心：普通のメモアプリは「消すのが能動・残すのが受動」。本アプリは逆で、**残すのが唯一の能動アクション**。
- 見返す努力はゼロ。復習のタイミング管理（忘却曲線）はアプリが担う。
- 消えることは失敗ではない。「手放した件数」も成果として表示する。

### ターゲット
- メモは取るが二度と見返さない人。メモアプリが死蔵メモで溢れている人。
- 覚えたい断片（人の名前、おすすめ、単語、用語、名言、手順、アイデアの種）が日常的に発生する人。

### やらないこと（コンセプトを守るための禁止事項）
- フォルダ／タグ／階層分類（分類コストが「とりあえず書く」を殺す）
- 溜めることを前提にした検索の作り込み（MVPでは検索なし）
- 通知の連打、ストリーク、ランキング等の罪悪感ギミック
- アカウント／サーバー／同期／共有（端末内完結）

## 2. アート方針（モックで確定）

- 世界の言葉： **静か／溶ける／紙の温かさ**
- 背景は紙色 `#FFFBF3`、本文はインク色 `#2B2620`
- 強い色は「暗記する」ボタンのピンク `#C2185B` の1点だけ。ぼかして見たときに押すべきものが1つ浮かぶこと。
- 補助色：オレンジ `#E65100`（期限が近い注意のみ）、紫 `#6A1B9A`（定着の進捗のみ）
- 警告に赤を使わない。期限は数字で脅さず、文字の薄さと残りバーで伝える。
- 角丸 16dp（カード）／チップ・ボタンは全丸。影は弱く。
- アニメーションは「薄れる」「浮かび上がる」など意味のあるものだけ。過剰にしない。

## 3. メモの状態遷移（この仕様の心臓部）

```
[書く] → FLOWING（流れる）
            ├─ 30日経過 → AFTERGLOW（余韻・7日） → 完全削除
            ├─「暗記する」→ LEARNING（定着中）
            │                  ├─ 間隔を最後までクリア → MASTERED（卒業）
            │                  └─「定着をやめる」→ FLOWING に戻る（期限は元の作成日から継続）
            ├─「流す」→ 状態は FLOWING のまま、その回の再会チェックポイントだけ消化
            └─「今すぐ消す」→ AFTERGLOW を経ず即・完全削除（確認ダイアログあり）
```

状態一覧：
| 状態 | 意味 | 表示場所 |
|---|---|---|
| FLOWING | 初期状態。全メモはここから始まる | ホーム（今日の再会／流れるメモ） |
| LEARNING | 暗記ボタンが押され、間隔反復中 | 定着タブ |
| MASTERED | 60日間隔までクリアし卒業 | 定着タブ下部（アーカイブ） |
| AFTERGLOW | 30日経過で消えた直後の7日間。復活可能 | 余韻タブ |
| （削除） | 余韻7日経過で完全削除。復元不可 | — |

重要な不変ルール：
- **30日の期限は作成日時が起点。編集しても延長されない**（編集で永命化できるとコンセプトが崩れる）。
- 複製したメモは新規メモとして新しい30日を持つ。
- LEARNING から FLOWING に戻した場合も、期限は元の作成日から数え続ける（戻した時点で30日を過ぎていれば即 AFTERGLOW）。

## 4. 再会アルゴリズム（FLOWING）

### チェックポイント
作成からの経過で、以下の5回が「再会」のタイミング：
**1時間後 / 翌日（24h）/ 3日後 / 7日後 / 14日後**

- アプリ起動時（および画面復帰時）に判定する。バックグラウンド処理・プッシュ通知は MVP では使わない。
- チェックポイント時刻を過ぎていて未消化のメモが「今日の再会」に入る。
- 「今日の再会」は **最大5件**。優先順位：①残り期限が短い順 ②チェックポイントの超過が大きい順。
- 5件を超えた分は翌回の起動時に繰り越す（消えたりしない）。
- カードが「今日の再会」に表示された時点で、そのチェックポイントは消化済みとする（見た＝再会した、が成立する設計。ボタンを押さなくてよい）。
- 「流す」ボタンは、その場でカードを枠から外す明示操作（消化は同じだが、ユーザーの意思表示として残す）。

### 薄れ表現
- 不透明度： `opacity = 1.0 − 0.78 × (経過日数 / 30)`、下限 0.22 でクランプ。
  - 0日目 1.00 / 7日目 約0.82 / 15日目 約0.61 / 28日目 約0.27
- 残りバー：残日数 / 30 を幅とし、ピンク→オレンジのグラデーション。
- 残り2日以下：残り日数ラベルだけオレンジにする（赤は使わない）。

### 消滅と余韻
- 起動時判定で経過30日を超えた FLOWING メモ → AFTERGLOW へ移動（ホームから消える）。
- AFTERGLOW は余韻タブでのみ表示。表示は題名（本文の1行目）＋薄表示。本文全文は「復活させる」を押すまで開かない。
- 余韻入りから7日経過で完全削除。以後の復元は不可（オンボーディングと余韻タブで明示する）。

## 5. 定着アルゴリズム（LEARNING）

「暗記する」を押した瞬間：
- 状態を LEARNING にし、ステージ 0、次回出題 = 翌日。

間隔ステージ（日数）： **1 → 3 → 7 → 14 → 30 → 60**
- 定着タブを開いたとき、期限到来分が「今日の定着チェック」として **1件ずつ** 出る（最大でその日の到来分すべて。1画面1件が原則）。
- 出題形式：
  - クイズ形式メモ（質問／答えを設定済み）：質問を表示 → タップで答えを表示 → 自己判定。
  - 通常メモ：本文を表示 → そのまま自己判定（表示ステップなし）。
- 判定ボタンは2つだけ：
  - **覚えてた** → ステージを1つ進め、次回 = 今日 + 次ステージ間隔。最終ステージ（60日）で「覚えてた」→ **MASTERED（卒業）**。
  - **あやしい** → ステージを1つ戻し（最小0）、次回 = 明日。責める文言・色は使わない。
- 卒業したメモは定着タブ下部の「身についたメモ」に静かに積まれる。再出題は MVP ではしない。

※モック段階の「3回連続で卒業」案は、分かりやすさとテスト容易性のため本仕様で「ステージ制（60日クリアで卒業）」に一本化した。

## 6. 画面仕様（モック準拠・3タブ＋モーダル）

※v0.2.0変更（2026-11-14 本人指示「もっとシンプルに、タブも一つに」）：§6.1〜6.3 の3タブ構成は廃止し、全セクションを単一画面の1スクロールに統合した。並びは 再会→定着チェック→流れるメモ→定着中→そろそろ消える→余韻→身についた→設定フッター。空のセクションは見出しごと出さない。§6.4〜6.7 は不変。

※v0.3.0変更（2026-11-14 UX見直し・独立審査の条件解消、本人が A+B 全採用を決定）：①再会中のメモは流れるメモに出さない（同一メモは画面に1回だけ）②「そろそろ消える」セクションは流れるメモ内の強調カード（薄れなし＋[暗記する][このまま消す]）へ統合 ③再会の消化は1メモ・1日・1チェックポイントまで（§4の読み替え：間隔を保つため。回数表示は消化済み数と一致）④保存は原子的保存＋破損時退避 ⑤定着中・卒業メモは行タップで詳細を開く（卒業は閲覧のみ＝§6.2どおり）⑥オンボーディングのスキップ時は消去告知の確認を挟む（§6.6の同意はこの確認＋書くモーダルの告知で担保）⑦再会カードでクイズ形式は質問のみ表示 ⑧保存・暗記直後の一言フィードバック。詳細はプロジェクト docs/UX_REVIEW_v0.2.md。

※v0.3.1変更（2026-11-14 本人の実機フィードバック）：①新規メモはダイアログでなく全画面で書く ②再会カードの主ボタンは「暗記する」でなく「👁見た」（再会は軽く受け止める場にし、残す判断は詳細と期限間近カードに置く）③「暗記する」の呼称は「残す」に統一 ④読込時に通常メモの題名が "null" になるバグを修正。

### 6.1 ホーム（タブ1）
- 主役：**今日の再会**。狙う気持ち：「あ、これ忘れてた」が気持ちいい。
- 構成（上から）：
  1. ヘッダー：アプリ名「うろぼえ」＋日付
  2. 今日の再会：§4 のカード最大5件。各カードに [暗記する] [流す]、残り日数、残りバー、チェックポイント表示（例：「3日前に書いた・3回目」）
  3. 流れるメモ：FLOWING 全件を新しい順。薄さ＝§4。タップで詳細へ
  4. FAB「＋」：書くモーダルを開く
- 空状態：
  - メモ0件：「まだ何も流れていません。最初の1行を書いてみて」
  - 今日の再会0件：セクション自体を出さない（静けさを保つ）

### 6.2 定着（タブ2）
- 主役：**今日の定着チェックの1件**。狙う気持ち：テストではなく再会クイズ。
- 構成：
  1. 進捗ドット：現在ステージまでの間隔列（1日 ✓ / 3日 ✓ / 7日目・今ここ / 14日 / 30日 / 60日）
  2. 出題カード（§5）
  3. [覚えてた] [あやしい]
  4. 下部：定着中の件数、卒業した「身についたメモ」一覧（タップで本文確認のみ）
- 空状態（到来分なし）：「今日のチェックはありません。次は ○月○日」

### 6.3 余韻（タブ3）
- 主役：**安心**（うっかり消去の救済が見えること）。
- 構成：
  1. そろそろ消える：残り2日以下の FLOWING メモ。[暗記する] [このまま消す（即削除・確認あり）]
  2. 消えたメモ（余韻）：AFTERGLOW 一覧。残り余韻日数と [復活させる]（→ FLOWING に戻す。ただし30日タイマーは作成日基準のため、復活直後の残りは短い。復活時は残り3日を保証する特例：復活日時に作成日時を「27日前」へ補正し、最低3日残す）
  3. 今月の成果：自然に覚えた（卒業＋定着中）件数／手放した（完全削除）件数。どちらも肯定的に表示

### 6.4 書くモーダル（FABから）
- 大きなテキスト入力1つだけ。保存ボタン1つ。
- 任意オプション（畳んでおく）：「クイズ形式にする」→ 質問／答えの2欄に切り替え。
- 保存時の補助文：「分類はしなくてOK。明日・3日後・7日後にまた顔を出して、30日後に消えます」
- 文字数制限： MVPでは 1,000字まで（長文メモはコンセプト外）。

### 6.5 メモ詳細（流れるメモのタップ先）
- 本文の編集、作成日、残り日数、再会履歴（何回再会したか）
- [暗記する] [今すぐ消す] [保存して閉じる]

### 6.6 オンボーディング（初回のみ・3枚）
1. 「書くだけでいい」— 分類も整理もいらない
2. 「忘れかけた頃、また出会える」— 忘却曲線で上部に浮かぶ
3. 「残したいものだけ、残る」— 暗記ボタンを押さないメモは30日で消える（この仕様をここで明確に同意してもらう）
- ヘルプから再表示可能にする。

### 6.7 設定（最小）
- データをすべて消す／アプリについて（バージョン、コンセプト説明）
- 通知設定は MVP に無い（プッシュなし）。
- ※v0.3.4追加（2026-11-15 UX見直し第2回 Y-2）：フッターに「データを書き出す」を追加。保存データ（JSON）を共有シートで外へ持ち出せる控え手段。利用者の手操作による書き出しのみで、同期・サーバー送信は引き続き行わない。あわせて About とオンボーディングに「アプリを削除するとメモもすべて消える」旨を明記する。

## 7. データモデル（端末内保存）

`memos` テーブル：
| カラム | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | |
| body | TEXT | 本文（通常形式） |
| question | TEXT NULL | クイズ形式の質問 |
| answer | TEXT NULL | クイズ形式の答え（question があれば body は使わない） |
| state | TEXT | FLOWING / LEARNING / MASTERED / AFTERGLOW |
| created_at | INTEGER (epoch ms) | 30日タイマーと再会判定の起点 |
| checkpoints_done | INTEGER | 消化済み再会チェックポイント数 0–5 |
| stage | INTEGER | LEARNING の現在ステージ 0–5（他状態では未使用） |
| next_due_at | INTEGER NULL | LEARNING の次回出題日時 |
| afterglow_at | INTEGER NULL | AFTERGLOW へ入った日時（7日期限の起点） |
| updated_at | INTEGER | |

- 日付判定は端末のローカル日付・時刻で行う。サーバー時刻は使わない。
- 端末時刻を過去に戻す等の異常時は、期限を「延ばす方向」にだけ倒す（消えるのが早まる事故を防ぐ）＝ 判定には記録済みの最大時刻も併用する簡易ガードを入れる。

## 8. 技術方針（推奨）

- Android先行。Kotlin + Jetpack Compose（大河の既存プロジェクトと同じ土俵）。
- ※v0.1.0実装時の変更（2026-11-14）：永続化は Room ではなく端末内JSONファイル保存で実装した（データモデル・項目は§7どおり。依存を増やさずこのVMのビルド環境で確実に通すための判断）。Roomへの移行は将来の選択肢として残す。
- バックエンドなし、アカウントなし、外部通信なし。権限要求なし（通知権限も不要）。
- 起動時＋画面復帰時に状態遷移（消滅・余韻明け削除・再会判定）を一括で評価するバッチ方式。常駐処理は作らない。
- iOS／クロスプラットフォーム化は MVP の検証後に判断。

## 9. 受け入れ条件（テスト観点）

1. メモを作成すると FLOWING でホーム下段に出て、残り30日・不透明度1.0で表示される。
2. 作成から（デバッグ時刻操作で）1時間・1日・3日・7日・14日経過後の起動で、そのメモが「今日の再会」に入り、表示された回だけチェックポイントが消化される。
3. 「今日の再会」は最大5件を超えず、超過分は次回起動に残る。
4. 経過日数に応じて不透明度と残りバーが §4 の計算どおりに変化する。
5. 30日経過でホームから消え、余韻タブに題名のみで出る。7日後に完全削除され、復活できなくなる。
6. 余韻から復活させると FLOWING に戻り、残りが最低3日ある。
7. 「暗記する」で定着タブの対象になり、翌日に出題される。
8. 「覚えてた」でステージが進み（1→3→7→14→30→60日）、60日で卒業して「身についたメモ」に入る。
9. 「あやしい」でステージが1つ戻り、翌日に再出題される。
10. クイズ形式メモは質問→タップで答え表示→判定の順に操作できる。通常メモは本文表示から直接判定できる。
11. メモを編集しても30日の残り日数は変わらない。
12. 空状態（メモ0件／再会0件／定着到来なし）で各文言が表示され、エラーにならない。
13. アプリを再起動・端末を再起動しても状態が保持される（端末内JSON永続化）。

## 10. MVPに含めないもの（v1.1以降の候補）

- ホーム画面ウィジェット（開かなくても再会できる）← 最有力候補
- 1日1回までの穏やかなローカル通知
- AIによるクイズ自動生成（通常メモ→質問／答え化）
- 音声入力・写真メモ
- 検索、同期、iOS版
- ※エクスポートは v0.3.4 で最小形（JSONの手動書き出し）のみ実装した（§6.7の改定注記参照）。自動バックアップや復元取り込みは引き続き含めない。

## 11. 検証のしかた（リリース前の身内検証）

※v0.3.4改定（2026-11-15 UX見直し第2回 Y-1）：旧版の「2週間で全項目を判定する」設計は、仕様の時間定数（消滅は作成30日後・卒業は最短115日）と合わず、合格ライン③④を原理的に測れなかった。検証を段階制に再定義する。

- 大河本人が実メモで使う。検証は段階ごとに判定し、前の段階の合格を次の段階の開始条件にしない（並行して進めてよい）。
- **第1段階（開始〜2週間）**：①書くのが面倒にならない ②再会が「うれしい」で「うるさい」にならない ③促されずに開いた日数（開く頻度そのものが中核の行動仮説）④定着チェックが回る（ステージが2つ以上進んだメモが1件以上ある）。
- **第2段階（30日超〜）**：⑤消えることに不安・後悔が出ない（消滅・余韻・復活を実際に体験してから判定する）。
- **第3段階（115日超〜）**：⑥1件以上、自然に卒業まで行く体験がある。
- どれかが崩れたら、機能を足す前に間隔・件数・文言のチューニングで直す。
