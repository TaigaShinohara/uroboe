# うろぼえ v0.4.1 不具合総点検（2026-11-19）

> 対応状況（2026-11-19）：本人の承認により、重大 B-1 と中 B-2・B-3 を **v0.4.2 で全件解消**した。低・観察（L-1〜L-4）は未着手として残す。

対象：v0.4.1（versionCode 15）の全ソース（MainActivity 1,324行／MemoLogic／MemoStore／Manifest）と仕様 v2.0 の突き合わせ。
前回の総点検（STABILITY_REVIEW_2026-11-16）は v0.3.x 世代のもので、本書が現行世代の正本。

## 重大

### B-1. `allowBackup="true"` でメモが端末の外へ出る（約束違反）
- AndroidManifest に `android:allowBackup="true"` があり、除外ルール（dataExtractionRules / backup_rules）が存在しない。
- このため Android の自動バックアップで `memos.json`（全メモ）と設定がユーザーの Google ドライブへ送信されうる。端末間移行でもコピーされる。
- About と仕様 §1 の約束「データはこの端末の中だけにあります」「アカウント／サーバー／同期／自動送信なし（端末内完結）」と矛盾する。
- 対処：`allowBackup="false"` にするか、抽出ルールで memos.json と prefs を除外する。

## 中（確実な分）

### B-2. 一覧カードで本文の1行目が二重に表示される
- 複数行の通常メモで、題名（1行目）の直下に本文プレビュー（全文＝1行目を含む）が表示され、1行目が重複する。
- 対処：プレビューは2行目以降を表示する（または題名と本文が重なる場合は本文側から1行目を除く）。

### B-3. save() のフォールバックが memos.json を直接上書きする
- `tmpFile.renameTo(file)` が失敗した場合の予備経路が `tmpFile.copyTo(file, overwrite = true)` で、保存先ファイルを直接書く。
- 書き込み途中の中断（容量不足・強制終了）で memos.json が破損しうる。次回起動で prev から復旧できるが、最大で直近1操作分を失う。
- 仕様 §6 の「memos.json 不在ウィンドウを作らない」という主張と厳密には矛盾する（rename 経路自体は正しい。予備経路だけが穴）。
- 対処：予備経路でも別名ファイルへ書いてから rename する形に変える。

## 低・観察（直さない判断も可）

- L-1. スワイプ確定処理は `LaunchedEffect(currentValue)` 経由で、再コンポーズのタイミングによっては二重発火の余地がある。ただし対象操作（またあとで／保留／復帰）はいずれも冪等で、実害はほぼ相殺される。
- L-2. 起動時に作る `memos.json.snapshot` は復旧経路（prev → tmp）で使われておらず、死にコードになっている（容量のみ消費）。
- L-3. EditScreen／WriteScreen の `take(1000)` は貼り付け時に無言で切り捨てる。上限到達後の入力でも編集履歴が積まれ、「戻す」が1回空振りすることがある。
- L-4. 60秒ごとの時刻更新で一覧が再ソートされるため、スワイプ操作の最中にカードが動く可能性がある（発生条件は稀）。

## 問題なしと確認した点（仕様 v2.0 との突き合わせ）

- 不変ルール：閲覧・編集（editBody）では reviewStage / lastReviewedAt を変更しない。画面回転でも発火しない。
- 忘却曲線ソート：Tier 0（Fresh 15分）／Tier 1（比率上限 2.0・同率は lastReviewedAt 古い順）／Tier 2 の順序と、「忘れかけ」ピル上位3件限定は仕様どおり。
- 「またあとで」：節目到達時は次ステージ＋reunions 加算、未到達時は起点更新のみで Fresh 猶予へ戻らない（仕様 §7-3 どおり）。
- 保存と復旧：tmp 書き出し＋fsync → prev へコピー → rename 置換の本経路は原子性を満たす。破損時は prev → tmp の順で自動復旧し、正当な全消去を復旧対象にしない。
- v0.3.x 移行：FLOWING / LEARNING は上段（LEARNING は stage+1）、AFTERGLOW / MASTERED は下段へ。旧「null」文字列の題名バグ対策も入っている。
- 削除は下段スワイプ／詳細［削除する］とも確認ダイアログ必須。上段スワイプに削除はない。
- Undo バナーは MemoStore 保持で画面回転に耐え、一覧に戻ってから自動消去タイマーが進む。
- ID の一意性（maxExisting+1 の併用）、時刻逆行ガード（maxSeen 永続化）、エクスポートはメモリ上の現在状態から生成。
