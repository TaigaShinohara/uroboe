# うろぼえ UX見直し記録（v0.2.0対象）

実施：2026-11-14 / 手順：concept-driven-ux（既存機能の体験改善）＋ independent-review
対象版：v0.2.0（versionCode 2、単一画面版）／ 範囲：見直しと報告まで（実装は本人の選択後）
審査環境：独立審査者は原資料（仕様・ART_DIRECTION・UI_CATALOG・実装コード）のみで判定し、ディレクターの結論は渡していない。

## コンセプト（判断軸）
メモを書く人が、忘却曲線に沿って勝手に再会することで自然と覚え、覚えたいものだけ「暗記する」を押して残し、押さなかったものは30日で自然と消える。見返す努力はゼロ。消えることは失敗ではない。

## 総合判定：条件付き合格（ディレクター・独立審査で一致）
条件：A1（同一メモの二重表示の解消）／A2（再会回数表示の誤り修正）／A3（保存破損時の全消失リスク解消＝本格運用前）
有効範囲：資料とコードから判断できる設計・実装の整合性のみ。実機での人間の感想（仕様§11の2週間検証）は未取得で、本判定はそれを保証しない。

## 独立審査の主な指摘（要旨・IDは審査報告のもの）
- X-1同一メモが「今日の再会」「流れるメモ」「そろそろ消える」に二重・三重表示される（単一画面化で露出）
- X-2「N回目の再会」表示が実際より1多い（消化後の値で+1している）。reunions の数え方も未定義
- X-3チェックポイント消化がカードの視認ではなく候補算出時点で一括発生する
- X-4卒業メモの本文に二度とアクセスできない（仕様§6.2「タップで本文確認」に反する）
- X-5オンボーディングのスキップで「30日で消える」告知を完全に回避できる
- X-6JSON直接上書き（非原子的）＋読込例外時の初期化で、破損＝全メモ無言消失の構造
- X-7色の役割逸脱2件（答え表示のピンク太字／「あやしい」のオレンジ）
- X-8クイズ形式メモは再会カードで答えまで露出する
- X-9定着中メモはチェック到来時以外、本文確認・編集手段がない
- X-10文書ドリフト（カタログ#7/#10/#11、仕様§9-13のRoom表記）＋卒業0件でも「身についたメモ」見出しが出る（自らの空セクション規則違反）
- X-11書くモーダルのクイズ切替常時表示（仕様は「畳む」）／1000字超過の無言切捨て
- X-12再会の優先順位②が仕様文言（超過順）と実装（経過時間順）で近似ズレ
- 最大の弱点（審査者）：「再会はアプリを開いたときにしか起きない」への全面依存。開かなければ再会は圧縮・喪失し、中核体験の成立は「促されずに開き続けるか」という行動仮説に懸かる。コードでは検証不能 → §11検証の最優先確認項目。崩れる場合は機能追加より先にウィジェット／穏やかな通知（仕様§10）の前倒し判断が要る

維持と判定されたもの（審査者）：書くモーダル、今日の再会、暗記ボタン、定着チェック、余韻・復活、詳細ダイアログ、設定フッター。

## ディレクター（パソパソ）側の評価と照合
一致した点：二重表示（X-1）、再会の間隔が開く頻度で崩れる問題（審査者の最大の弱点＋X-3 と、こちらの「チェックポイント一括消化で間隔が潰れる」指摘は同根）。
審査者が見つけ、こちらが見落とした点：X-2（回数表示のoff-by-one、実バグ）、X-6（保存の原子性＝「消えるアプリ」への信頼の土台）、X-4（卒業本文に届かない）。
こちらからの追加：
- M-1：そろそろ消える（救済セクション）のカードまで薄れている。救う場面こそ不透明度100%であるべき。X-1の統合方向（流れるメモ側へ寄せ、残り2日以下は完全な濃さ＋ボタン付きで強調）と一体で解消する。
- M-2：保存直後・「暗記する」直後に手応えが何もない（ダイアログが閉じる／カードが消えるだけ）。唯一の能動アクションの達成感がゼロで、押せたか不安になる。小さな一言フィードバックを推奨（仮説：感情面は人間の確認が必要）。
- M-3：1日の露出量に全体キャップがない（再会5件＋定着チェック複数件が同じ日に重なりうる）。テンション配分の観察項目。
- 間隔の保持（こちらの当初案）：チェックポイント消化を「1メモにつき1日1つまで」にすると、不定期に開いても間隔が潰れない。X-3の解消条件（視認ベース消化）とは別軸で両立可能。

## v0.3 修正候補（優先順）
### A：必須（条件付き合格の解消条件）
- A1 = X-1＋M-1：重複解消。再会表示中のメモを流れるメモから除外。「そろそろ消える」は独立節をやめ、流れるメモ内の該当カードを完全な濃さ＋オレンジ＋[暗記する][このまま消す]付きに変える
- A2 = X-2：再会回数を消化前のチェックポイント番号で表示。reunions は「露出回数」と定義して一致させる
- A3 = X-6：保存を tmp＋rename の原子方式に。破損検出時は既存ファイルを退避してから開始
### B：推奨
- B1 = 間隔保持：チェックポイント消化を1メモ1日1つまで（X-3の視認ベース化は次段で検討し、現行の「表示＝消化」は仕様文言どおりと明記）
- B2 = X-4＋X-9：定着中・卒業メモの行タップで詳細ダイアログを開く
- B3 = X-5：オンボーディングをスキップする際に「押さなかったメモは30日で消えます」の1行確認を挟む
- B4 = M-2：保存・暗記直後の小さな一言フィードバック
- B5 = X-8：再会カードではクイズ形式は質問のみ表示
- B6 = X-10＋X-11＋X-12：カタログ・仕様のドリフト解消、卒業0件時の見出し非表示、字数超過時の注記
### C：観察（今回は直さない）
- X-7（色の小逸脱）、M-3（1日の露出キャップ）、オンボーディングの体験化、卒業の見せ方の格上げ

## コンセプト達成の最終照合（v0.2.0時点）
| コンセプト要素 | 判定 | 根拠 |
|---|---|---|
| 書く負担が最小 | 実現 | コード確認（1欄＋保存1ボタン） |
| 勝手に再会する | 部分的に実現 | 開いた時だけ・間隔が開く頻度で圧縮される（最大の弱点） |
| 暗記したものだけ残る | 実現 | コード確認（状態遷移・不変ルール） |
| 押さないものは30日で消え、余韻7日 | 実現（ただし信頼リスク） | コード確認。破損時の無言全消失リスク X-6 が残る |
| 見返す努力はゼロ | 実現 | 導線確認（単一画面・上部配置） |
| 消えることが失敗でない気持ち | 未確認 | 成果表示はあるが地味。人間の感想が未取得 |
| 自然と覚えられる | 未確認 | 仕様§11の2週間実メモ検証が必要 |

## 実装結果（2026-11-14 追記）
本人が「A+B全部」を選択し、v0.3.0（versionCode 3）で実装・納品済み。A1〜A3・B1〜B6 すべて反映：重複解消と「そろそろ消える」の統合（流れるメモ内の強調カード、濃さ100%）、回数表示の一致、原子的保存＋破損時退避（memos.json.corrupt-* へ退避）、1日1チェックポイント消化（lastReunionEpochDay を追加、旧データはデフォルト0で互換）、定着中・卒業メモの行タップ詳細（卒業は閲覧のみ）、スキップ時の消去告知確認、保存・暗記の一言フィードバック、再会でのクイズ答え非表示、カタログ0.3／仕様§6注記・§7・受け入れ条件13の整合、卒業0件時の見出し非表示、900字以上の残り字数表示。単体テストは新規2件を追加しコンパイル確認まで（実行はVMのテスト実行環境の不具合で未確認、従来どおり）。これにより条件付き合格の条件A〜Cは解消済み。残るのは実機での人間の体験確認（§11の2週間検証）のみ。
